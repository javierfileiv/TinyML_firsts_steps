# edge_ai — 3D gesture recognition on STM32 BlackPill (TinyML)

A production-grade Edge AI / TinyML application running bare-metal on an
STM32 BlackPill (STM32F411CEU6) with an InvenSense MPU6050 6-axis IMU,
under Zephyr RTOS. The device classifies dynamic 3D gestures in real time
from a fixed 256x6 sample window, with on-device inference through
TensorFlow Lite for Microcontrollers.

Core constraints:

- Deterministic real time on Zephyr RTOS, sampling at exactly 100 Hz
- Zero dynamic allocation: every buffer is static (`.bss`/`.rodata`)
- The int8 model (~11 KB) and the 13.9 KB tensor arena live entirely in
  the chip's 512 KB Flash and 128 KB SRAM; latency profiling is on the
  roadmap (target: milliseconds per window)
- Model weights stored in Flash as an aligned `const` C array, int8
  Post-Training Quantization end to end

## Hardware

| Signal | Pin | Note |
| --- | --- | --- |
| I2C1 SCL | PB8 | MPU6050 @ 0x68, 400 kHz |
| I2C1 SDA | PB9 | |
| MPU INT (data-ready) | PA2 | Rising-edge EXTI, DRDY driver |
| KEY button | PA0 | Active low, internal pull-up — manual capture trigger |
| User LED | PC13 | Active low — capture/window feedback |
| Console | USB CDC ACM (`/dev/ttyACM0`) | Logging, `dfu` reflash trigger, space capture command, `w` watch toggle |

Board: WeAct Studio BlackPill V2/V3 (`blackpill_f411ce`), 96 MHz SYSCLK,
100 Hz sampling reached by hand-configured DLPF + SMPLRT_DIV (see
`src/imu.c`), sensor ranges +/-4 g and +/-1000 deg/s.

## Firmware structure

- `src/main.c` — capture state machine (IDLE / ACQUIRE / COOLDOWN).
  Triggers: KEY button on PA0 and the console `space` command. The
  automatic gyro-energy trigger exists but is compile-switched off
  (`ENABLE_AUTO_TRIGGER`). The main loop only advances on DRDY interrupt
  samples so every recorded sample is exactly 10 ms apart. On every
  completed window the TFLM model runs and the board prints its
  verdict; watch mode (`w`) silences the CSV dump so the board speaks
  only in detections.
- `src/imu.c/h` — MPU6050 bring-up: manual register configuration for
  exact 100 Hz (DLPF bypassing + SMPLRT_DIV), DRDY interrupt hooked to
  PA2, polled reads of the 14 registers per sample.
- `src/capture.c/h` — pre-buffer of 16 samples (160 ms) kept rolling in
  IDLE to preserve the gesture attack, fixed 256-sample capture window,
  CSV dump framed by `BEGIN`/`END` markers, `capture_window()` accessor
  feeding the inference driver.
- `src/dfu_boot.c/h` — reusable "jump to ROM DFU bootloader" module for
  any STM32F4 Zephyr project: when `dfu` is typed on the console, it
  hands the Cortex-M over to the system bootloader with a warm handover
  (soft USB disconnect, clock tree restored to its reset state,
  SysTick stopped, NVIC disarmed, VTOR/MSP swapped), so the board
  re-enumerates as 0483:DF11 and can be reflashed without any button.
  Drop it in another app with its header unchanged.
- `model/` — the trained model and its driver:
  - `inference.cc/h` — TFLM `MicroInterpreter` wrapper: z-score
    normalization of the raw window, int8 quantization on the way in,
    de-quantization of the two output probabilities.
  - `model_data.h` — the int8 model blob generated by the training
    notebook (~11 KB).
  - `model_params.h` — every constant the driver needs (z-score
    mean/std, input scale/zero-point, output scale/zero-point),
    generated from the converted model itself; never edited by hand.
- `boards/blackpill_f411ce.overlay` — I2C1 pin muxing, MPU6050 node with
  INT on PA2, USB CDC ACM console mapping.
- `prj.conf` — USB device stack, console, sensor, GPIO, C++ and TFLM.

## Host tool

`tools/capture.py` listens on the serial console, catches `BEGIN`/`END`
CSV windows and stores them as `dataset/<class_name>/sample_XXX.csv`.
The numbering scans the existing files first, so captures are never
overwritten, even across sessions.

```sh
python tools/capture.py -p /dev/ttyACM0 -c IDLE -d 2   # idle class, 2 s settle
python tools/capture.py -p /dev/ttyACM0 -c A           # gesture class A
python tools/capture.py -p /dev/ttyACM0 --watch        # detections only, no files
```

- Press **Space** in the tool's terminal: it waits the settle delay
  (`-d`, default 0.4 s), then sends the trigger byte to the board. The
  window then records the gesture performed during those seconds.
- The KEY button on the board also starts a capture.
- Detection lines get a `det:` prefix; with `-w` nothing is ever
  written to the dataset.
- Typing `w` (in tio, or in the tool's terminal) toggles watch mode on
  the board: the CSV dump goes silent and only the detections are
  printed — the final-product voice.
- Every window is validated and required to contain exactly 256 rows;
  malformed or short frames are dropped with a warning.
- `q` or Ctrl-C quits and restores the terminal.

## Training (`notebook_jupiter/train_v2.ipynb`)

One notebook does the whole loop: dataset scanning, physical validation
of every capture (peak angular-rate and timing rules per class, rejects
move to `quarantine_<class>/` folders), training of the spec 1D-CNN,
int8 post-training quantization, and a quantized-model check in Python
that measures the probability drift introduced by quantization before
anything reaches the board.

Run it with Jupyter from the repository root (`dataset` is resolved
relative to it). By default **every capture goes to training** — the
field test on the board is the referee; set `USE_HOLDOUT = True` in the
config cell for honest holdout evaluation when comparing method
variants. The last cells write `model/model_data.h` and
`model/model_params.h` directly into `model/`, so a retrain followed by
`west build` + `dfu` + flash is the entire update cycle — no constant
ever gets hand-patched.

Commit hygiene: purge the notebook outputs before committing (Edit >
Clear All Outputs in Jupyter) so the repository stays diffable and free
of embedded base64 blobs.

## Building and flashing

```sh
source env.sh          # venv + gnuarmemb toolchain + tflite-micro module path
west build -p auto -b blackpill_f411ce
```

Memory budget today: ~185 KB Flash, ~37 KB SRAM (13.9 KB tensor arena
reserved, ~10.7 KB actually used by the current model).

First flash, or whenever the DFU path misbehaves: hold BOOT0, press and
release RESET, run:

```sh
west flash    # dfu-util runner, re-enumeration as 0483:df11
```

Reflash without touching any button once the app runs: in `tio
/dev/ttyACM0`, type `dfu`. The board hands itself over to the ROM
bootloader, `lsusb` shows `0483:df11`, then `west flash` renews the
application. A build marker (`[dfu vX]`) in the boot line identifies
which build is running on the chip.

Note: print lines emitted before the host enumerates the CDC device are
lost; open the console first, then press RESET, to see the boot.

## Signal pipeline (spec summary)

- Window: 256 samples x 6 channels (ax, ay, az, gx, gy, gz), 2.56 s at
  100 Hz
- Trigger: KEY press (gyro-energy trigger behind the
  `ENABLE_AUTO_TRIGGER` switch); 500 ms cooldown after each window
- Preprocessing: per-channel z-score with the exact constants from
  `model/model_params.h`, int8 quantization
- Model: 1D-CNN — Conv1D(16, k=5) + MaxPool2, Conv1D(32, k=3) +
  MaxPool2, GlobalAveragePooling1D, Dense(16), softmax
- Runtime: TFLM, full int8 PTQ; dense layers are per-tensor quantized
  because this TFLM revision does not support per-channel
  FULLY_CONNECTED kernels

## Dataset guidance

The current harvest lives in `dataset/`: 100 validated windows (A: 54,
IDLE: 46) and the `quarantine_*/` folders that keep the 36 rejected
captures for inspection.

- `dataset/IDLE/`: the rejection class. Record plenty, mixing rest,
  walking and deliberate desk bumps; keep it free of anything
  resembling a target gesture.
- `dataset/A/`, `dataset/B/`, ...: the target gestures, several speeds
  and hand orientations.
- Variety across recording sessions beats volume captured in one
  sitting: the model must not memorize one session.
